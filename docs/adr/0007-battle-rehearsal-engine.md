# 0007 战斗推演模拟引擎：可回退任意行动 + LLM 交互式指挥（用户决策）

> 状态：已批准。用户明确项目核心定位：**高度模拟星穹铁道官方战斗逻辑的程序**，
> 支持**回退任意行动**，**整个流程由 LLM 自主掌控**。
> 本文档是 grilling 会话（10 项决策逐条确认）后的需求固化；与 ADR-0006（五层地基）配套：
> 0006 保证"模拟可信"，0007 定义"可信之上如何被使用"。

## 一、需求要点（用户原话）

1. 高度模拟星穹铁道官方战斗逻辑的一个程序
2. 可以回退任意行动
3. 整个流程可以被 LLM 掌控
4. 用户不操作战斗流程，只让 LLM 操作（用户是旁观者/验收者，保留最终仲裁权）

## 二、已确认决策（grilling 逐条确认）

### D1 随机性：固定 seed 随机（RNG 入事件流）
真实战斗的暴击判定、敌人 AI 选择是随机的。模拟器内建 RNG，**RNG 状态作为事件流的一部分**
（事件溯源序列化 RNG 状态）——undo 后重放同一 seed 结果完全一致，回退依然成立；
LLM 可分支探索"暴击线/不暴击线"。不用纯期望值（不够"高度模拟"）、不用双模式（行为不统一）。
优化器/策略搜索侧可继续用期望值模式，互不干扰。

### D2 决策空间：对齐官方真实规则
LLM 只能决策**官方规则里玩家能控制且当前合法**的动作：
- 主动行动（当前行动角色、可用技能、合法目标）
- 大招释放时机（官方为玩家手动——能量满可不立即放；作为 act 参数携带，非独立一步）

决策边界必须在执行前裁剪/拒绝非法动作：SP 不足的战技不进入 `decision.skills`，直接请求也必须报错，
不得依赖底层 legacy 的“战技静默降级普攻”；友方单体技能必须选合法存活队友；只有满能、存活角色的大招可设为释放。
每个 `skill_options` 还必须暴露结构化 `mechanics`，LLM 只能据此描述本次技能效果；例如忆灵已在场且技能无
`summon=true` 时，不得把充能技能说成召唤技能。报告记录**实际执行技能与实际目标**，不能把请求动作冒充结算动作。

以下全部由模拟器按官方规则自动执行，不进决策空间：追击/协奏/真伤/击破结算、忆灵行动、
敌人 AI、受击回能/击杀回能。

### D3 回退粒度：act 级，分支只在 act 边界
一次 act = 一个决策单元（主动行动 + 该步大招指令 + 其全部自动连锁）。undo 撤销整个 act，
回到决策前状态。**同一完整回合内的额外行动不结算 buff/debuff 持续回合**；持续时间只在角色进入
下一个完整回合时递减一次，额外行动链内保持不变。**禁止事件级回退**（自动连锁由规则决定，不可分割；事件级回退违反官方规则
且分支树爆炸）。分支只能在 act 边界分叉。

### D4 undo 发起：LLM 自评 + 用户仲裁
- LLM 每步 act 后自评（observe 反馈），不满意主动 undo 换决策；带预算防失控：
  每步最多 **3 次**回退尝试，全局 **50 次**（可配置）
- 用户不操作战斗，但保留最终仲裁权（要求重新推演/换配置）

### D5 配置边界：变更 = 冻结旧树开新会话
**配置（Setup）** = 队伍（成员+面板+光锥+星魂）+ 敌人构成 + 关卡/靶场规则 + 场地 buff + 随机 seed + **开战准备**。
开战准备显式记录已使用秘技与最终保留的领域；同类领域最多保留 1 个，知更鸟/记忆主领域互斥。
秘技结算发生在首个 act 决策点之前，实际生效结果必须进入模拟器状态、事件日志与报告；它不是可由 act undo 修改的战斗内决策。
任何配置变更 → 旧推演树冻结为历史参考（不参与当前决策），开新会话，**undo 栈清空，undo 永不跨配置**。
LLM 可显式"提议配置变更"（如"换充能绳"或"改用另一秘技领域"），但它是会话重置动作，不可 undo。

### D6 推演目标：开放式，LLM 自主收敛
场景不定义目标；LLM 自己决定"什么叫好"、何时收敛。模拟器只保留物理边界：
行动条推进到 target_av 耗尽 / 敌人全灭 / 我方全灭 → 自动终止。

### D7 界面：完整推演报告
`python -m hsr_sim.rehearse` 启动，LLM 自主跑完整流程，输出：
**决策轨迹**（每一步实际由谁用什么技能打谁、大招时机、SP 前值→后值与净变化）+ **分支树摘要**（尝试过哪些路线、为什么放弃、
最终选了哪条）+ **最终状态**（伤害/击杀/SP/能量/时间线）+ **明确终止原因**。LLM 的自由文本只标作
“LLM理由（未经规则验证）”，不得与模拟器结算事实混写。行动顺序后端仍必须同时维护：
1. 当前行动条中每个在场我方、敌方与忆灵的**下一次行动顺序**（距行动 AV + 预计绝对时刻）；
2. 来自可回退事件日志的**完整实际行动顺序**（我方主动行动、即时终结技、敌方行动、忆灵行动）。
两者均由模拟器状态直接投影，禁止前端自行推算；undo 后必须随状态一同回退。WebUI 当前按用户要求暂时隐藏行动顺序区域，
但不得删除后端投影、事件日志或报告中的实际行动顺序。WebUI 同时显示由模拟器投影的战斗内动态角色面板：基础值、当前有效值、
增益/减益来源与剩余时间；buff 获得、失效和 undo 后必须同步更新。`--brief` 只给结论；WebUI 报告支持文本选择和一键复制，
且状态轮询仅在报告内容变化时更新 DOM，避免打断用户选区。

### D8 多波次：事件流天然支持
事件溯源不设波次边界，跨波次回退/分支架构上直接成立；P1 做真实关卡（混沌回忆多波）时启用，
P0 靶场仍单场景。

### D9 分支对比：结构化数据，不预设指标
observe 提供结构化全量数据（伤害/击杀状态/SP 曲线/行动次数/时间线/能量），
由 LLM 按自己定的目标解读；系统不替 LLM 判断好坏。

### D10 LLM 知识包与成本预期
- system prompt = 游戏知识精简包（机制规则 + 当前队伍技能/敌人数据 + **信任度信封**：
  未实测值（wiki/手填）明确告知，防止 LLM 把近似值当真理）+ observe 状态
- 每次决策/自评请求保留已接受的历史选择，并附带当前路线与放弃分支摘要；undo 后当前路线缩短但放弃路线仍可见。
- 一局完整推演 ≈ 20–60 次 LLM API 调用（每步 act + 自评）——交互式指挥的固有成本；
  策略搜索仍是廉价自动试错的补充，两者并存
- 收敛兜底：全局回退预算耗尽 → 强制 LLM 从现有分支选最优并汇报（防空转）

## 三、架构约束

### 3.1 两层状态模型（配置层 / 决策层）
- **配置层**（Setup）：不可被 undo 触及；包括开战准备（秘技清单、保留领域与攻击入战者）；变更 = 新会话（D5）
- **决策层**（Decision）：act 序列 + 分支树；undo/branch 只作用于此层
- 秘技/开战准备先于首个决策点结算；实际生效效果进入事件流，但始终保留在初始快照内
- 领域语义：同类领域最多 1 个；知更鸟领域与记忆主领域不能同时生效
- 领域语义：undo 的前提是配置未变（用户原话："面板属性光锥星魂都没变，undo 只能重新做决策"）

### 3.2 事件溯源（支撑回退）
- 状态 = 事件流重放结果；事件不可变、可序列化、可重放
- RNG 状态纳入事件流（D1）；每角色行动打快照加速（回退 = 最近快照 + 增量重放）
- 模拟无副作用、确定性（同 seed 同序列 → 同结果）

### 3.3 环境-智能体接口（LLM 指挥）
```
observe()      → 完整状态（行动条/SP/能量/韧性/buff/敌人HP）+ 事件摘要 + 分支对比
act(decision)  → {actions: [{unit, skill, target}], ults: {cid: 放/不放}}
undo()         → 撤销最近一次 act（LLM 自评用；受 D4 预算约束）
restart()      → 回到初始状态
branch_stats() → 各分支结构化对比（D9）
propose_setup(new_setup) → 配置变更 = 新会话（D5）
```

## 四、对迁移路径的影响（0006 八修订）

| 阶段 | 变化 |
|---|---|
| P0-0..P0-1 | 不变（P0-1 已完成） |
| P0-2 | 不变（公式 + 事件语义先锁）；事件语义新增两条：**事件不可变/可重放**、**RNG 入事件流** |
| P0-3 | Effects + Event Engine：事件溯源执行器 + 快照 + undo/restart 原语 + 回放一致性测试 |
| P0-4..P0-6 | 不变（对账/实测） |
| P1 | LLM 指挥接口（observe/act/undo/restart）提前为首项；Optimizer 降为上层应用之一；真实关卡（多波次） |
| P2 | LLM = 战斗指挥模式为主，面板建议模式保留 |

## 五、明确不做

- 用户逐步操作界面（无 UI 交互，LLM 全自主；D7 报告即产出）
- 事件级回退（D3）；undo 跨配置（D5）
- 网络/多人；替代游戏本体（数值以 T3/T4 对账为准）
